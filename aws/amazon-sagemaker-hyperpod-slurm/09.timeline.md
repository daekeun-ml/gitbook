# 09. 최근 기능 타임라인 (Slurm, 2023-H2 → 2026-H1)

***

### 0. 한눈에 보는 타임라인

Slurm은 HyperPod의 **원조 모드**(2023-11-29 GA, EKS보다 \~10개월 먼저)입니다. 이후 복원력(HMA·deep health check·auto-resume)·AMI(Ubuntu 22.04, Slurm 24.11→25.11)·용량(FTP·continuous provisioning)이 꾸준히 추가됐습니다.

> ⭐ **가장 헷갈리기 쉬운 변화 (2026-02)**: 클러스터 **설정 방식이 "스크립트+S3 파일(레거시)" → "AMI 자동설치 + API 역할지정"** 으로 바뀌었습니다. 옛 자료를 따라 하면 신규 권장 방식과 충돌할 수 있으니, 클러스터를 새로 만든다면 03 §2 "옛 방식 vs 신규 기본"을 먼저 보세요.

***

### 2. 범주별 "지금 중요한 것"

* **복원력 성숙**: deep health check → GRES requeue(2024-08) → **Slurm HMA(2025-09)** → 온디맨드 deep health check(2026-04). 순수 Slurm 대비 매니지드 복원력이 꾸준히 강화.
* **⭐ 설정 방식 대전환 (2026-02)**: **API-driven Slurm 설정**으로 기본이 바뀜 — 예전엔 S3의 `provisioning_parameters.json`(레거시)로 역할을 정하고 스크립트로 설치했지만, 이제 **API로 역할 지정 + 스크립트 없이 AMI 기반 생성**이 권장. 옛 자료와 헷갈리기 쉬우니 03 §2의 "옛 방식 vs 신규 기본"을 먼저 보세요. (Continuous·멀티-헤드 등 최신 기능도 이 API 기반을 전제로 함.)
* **AMI/Slurm 버전**: 20.04→**22.04(2025-05)**, Slurm 23.02→23.11→**24.11→25.11**. EFA-on-FSx는 22.04부터.
* **용량 & 프로비저닝**: **용량 확보**는 Flexible Training Plans(예약)로, **프로비저닝 방식**은 **Continuous Provisioning(2026-03, `NodeProvisioningMode`)** 으로 — 예약한 용량을 "다 모이면 한 번에" 대신 "잡히는 대로 점진 충원". (Continuous는 용량 옵션이 아니라 별개 축 → 03 §5.1)

***

### 3. ⚠️ Slurm에 **없는** 것 (EKS 전용 — 혼동 주의)

타임라인을 볼 때 헷갈리기 쉬운 EKS 전용 기능들 — **Slurm 타임라인엔 등장하지 않습니다**:

* **Managed Tiered Checkpointing**(2025-09-08, EKS 전용) · **Task Governance**(2024-12, EKS) · **MIG**(2025-11, EKS) · **Inference Operator/KV캐시/지능형 라우팅**(EKS) · **`hyp` CLI v3**(EKS) · **flexible instance groups**(2026-04, EKS).
* 자세한 구분은 08. EKS vs Slurm.
