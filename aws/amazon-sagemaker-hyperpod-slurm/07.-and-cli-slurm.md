# 07. 옵저버빌리티 & CLI 운영 (Slurm)

***

### 0. TL;DR

1. **클러스터 운영 CLI는 `aws sagemaker`(boto3)** — `create-cluster`/`update-cluster`/`update-cluster-software`/`list-cluster-nodes` 등. **`hyp` CLI는 EKS 전용**이라 Slurm 클러스터를 관리하지 않습니다.
2. **잡/노드 모니터링은 Slurm 네이티브** — `squeue`/`sinfo`/`scontrol`/`sacct`.
3. **메트릭 옵저버빌리티는 DIY** — 라이프사이클 `enable_observability=True`로 DCGM exporter·node exporter·Slurm exporter·Prometheus를 노드에 설치하고, **Amazon Managed Prometheus(AMP) + Managed Grafana(AMG)** 를 직접 연결. (EKS의 1-click 애드온 같은 매니지드 통합 아님)
4. **CloudWatch 메트릭**(CPU/GPU/메모리·노드 수)은 `/aws/sagemaker/Clusters` 네임스페이스에 기본 on(2024-12-13\~).

***

### 1. 클러스터 운영 — `aws sagemaker` (hyp CLI 아님)

```bash
# 클러스터/노드 조회
aws sagemaker list-clusters
aws sagemaker describe-cluster --cluster-name ml-cluster
aws sagemaker list-cluster-nodes --cluster-name ml-cluster
aws sagemaker describe-cluster-node --cluster-name ml-cluster --node-id i-0abc...

# 스케일 / 패치 / 삭제
aws sagemaker update-cluster --cli-input-json file://update_cluster.json
aws sagemaker update-cluster-software --cluster-name ml-cluster   # 루트 볼륨 교체, 백업 먼저
aws sagemaker delete-cluster --cluster-name ml-cluster            # controller는 단독 삭제 불가
```

> ⚠️ **`hyp` CLI / Python SDK(`sagemaker-hyperpod`)는 EKS/Kubernetes 전용**입니다(training-job = `HyperPodPyTorchJob` CRD, inference endpoint = K8s CRD). Slurm 클러스터는 위 `aws sagemaker`(또는 boto3)로 관리하고, 잡은 노드에서 Slurm 명령으로 다룹니다.

출처: [Slurm 운영 CLI](https://docs.aws.amazon.com/sagemaker/latest/dg/sagemaker-hyperpod-operate-slurm-cli-command.html) · [hyp CLI(EKS 전용)](https://github.com/aws/sagemaker-hyperpod-cli)

***

### 2. 잡 / 노드 모니터링 — Slurm 네이티브

```bash
# (로그인/컨트롤러 노드에서, SSM 접속 후)
squeue                       # 큐·실행 중 잡
squeue -u $USER
scontrol show job <jobid>    # 잡 상세
sinfo -a -N -l               # 노드·파티션 상태(idle/mix/drain/down/fail)
scontrol show node=<ip>      # 노드 상세
sacct -j <jobid> --format=JobID,JobName,State,Elapsed,MaxRSS,ReqGRES   # 어카운팅(완료 잡)
```

* **`sacct`/어카운팅**: controller의 `slurmdbd` + MariaDB(또는 RDS)로 자동 구성(라이프사이클 `setup_mariadb_accounting.sh`/`setup_rds_accounting.sh`). 잡별 자원 사용·과금 집계.
* **거버넌스**: Slurm에선 **파티션·QOS·fair-share**가 EKS Task Governance(Kueue)의 역할을 합니다(Slurm 네이티브).

출처: [Slurm 잡 실행/모니터링](https://docs.aws.amazon.com/sagemaker/latest/dg/sagemaker-hyperpod-run-jobs-slurm.html)

### 3. 메트릭 옵저버빌리티 — DIY (Prometheus + Grafana)

EKS의 1-click 애드온과 달리, Slurm은 **직접** 구성합니다(라이프사이클로 자동화 가능):

* 라이프사이클 `config.py`의 **`enable_observability=True`** + `ObservabilityConfig`(`prometheus_remote_write_url`, `nccl_metrics_enabled`)로:
  * worker 노드: `install_dcgm_exporter.sh`(GPU), `install_efa_node_exporter.sh`(고속망)
  * head 노드: `install_slurm_exporter.sh`(Slurm 메트릭), `install_prometheus.sh`
  * 선택: **NCCL Inspector** TaskProlog(`/opt/slurm/etc/task_prolog.sh`)로 NCCL 메트릭을 node\_exporter textfile로.
* 이 메트릭을 **Amazon Managed Service for Prometheus(AMP)** 에 remote-write하고, **Amazon Managed Grafana(AMG)** 워크스페이스에서 시각화 — 둘 다 **직접 셋업**.

| 지표 출처                 | 무엇                          |
| --------------------- | --------------------------- |
| **DCGM exporter**     | GPU 온도·전력·사용률·XID 오류·NVLink |
| **EFA node exporter** | 고속망 RX/TX·RDMA              |
| **node exporter**     | CPU·메모리·디스크                 |
| **Slurm exporter**    | 큐·노드 상태·잡 통계                |

출처: [Slurm 클러스터 옵저버빌리티](https://docs.aws.amazon.com/sagemaker/latest/dg/sagemaker-hyperpod-cluster-observability-slurm.html) · [Slurm exported metrics 레퍼런스](https://docs.aws.amazon.com/sagemaker/latest/dg/sagemaker-hyperpod-cluster-observability-slurm-exported-metrics-reference.html)

### 4. CloudWatch (기본 제공)

* `/aws/sagemaker/Clusters` 네임스페이스에 CPU/GPU/메모리 사용률·전체/실행/실패 노드 수 등이 **기본 on**(2024-12-13\~). 알람 설정 가능.
* 라이프사이클 로그: 각 CreateCluster 실행이 CloudWatch 로그 스트림(`<cluster-name>-<timestamp>`)에 stdout/stderr.
* HMA 이벤트: `/aws/sagemaker/Clusters/`의 `SagemakerHealthMonitoringAgent` 스트림. deep health check: `DeepHealthCheckResults/...` + 노드 `/var/log/aws/clusters/sagemaker-deep-health-check.log`.

출처: [릴리스 노트(CloudWatch 메트릭)](https://docs.aws.amazon.com/sagemaker/latest/dg/sagemaker-hyperpod-release-notes.html)
