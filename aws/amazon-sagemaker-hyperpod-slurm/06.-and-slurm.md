# 06. 체크포인트 & 스토리지 (Slurm)

***

### 0. TL;DR

1. 공유 FS는 **FSx for Lustre, `/fsx`에 하드코딩 마운트**(라이프사이클 `mount_fsx.sh`).
2. **auto-resume는 결함 노드를 항상 "교체"** 하므로, 로컬 NVMe(`/opt/dlami/nvme`)의 체크포인트는 **소실**됩니다. → 체크포인트는 **반드시 `/fsx`(또는 S3)** 에.
3. ⚠️ **Managed Tiered Checkpointing(CPU-RAM tier + peer 복제 + S3)은 EKS 전용**(GA 2025-09-08, "Amazon EKS HyperPod clusters"로 스코프). 2026-06 기준 Slurm 미지원.
4. Slurm에선 **직접 계층화**: `/fsx`에 async DCP 자주 + S3에 주기적으로. **FSx↔S3 DRA**로 S3 export 자동화 가능.

***

### 1. `/fsx` — 공유 스토리지

* 라이프사이클 `lifecycle_script.py`가 `mount_fsx.sh`를 **`/fsx`** 인자로 호출해 FSx for Lustre를 전 노드에 마운트(`noatime,flock,_netdev,x-systemd.automount`, `<dns>@tcp:/<mountname>`).
* 같은 AZ 권장(cross-AZ 트래픽·비용 회피). FSx OpenZFS는 선택적으로 `/home`에.
* `/fsx`에 두는 것: 코드, 데이터셋, 컨테이너 `.sqsh`, **체크포인트**, 로그.

### 2. 노드 교체에서 살아남는 규칙

| 위치                            | 노드 교체 시    | 체크포인트 적합?     |
| ----------------------------- | ---------- | ------------- |
| **로컬 NVMe** `/opt/dlami/nvme` | **소실**(휘발) | ❌ 절대 단독 사용 금지 |
| **`/fsx`** (FSx Lustre)       | 생존(별도 FS)  | ✅ 권장          |
| **S3**                        | 생존(내구성 최고) | ✅ 아카이브/원격     |

> 05에서 본 대로 auto-resume은 노드를 **항상 교체**합니다. NVMe 체크포인트는 교체와 함께 사라지므로, "이어서 학습"하려면 `/fsx`나 S3에서 로드해야 합니다.

### 3. ⚠️ Managed Tiered Checkpointing은 EKS 전용

EKS 가이드의 그 기능(CPU RAM 1차 + RDMA peer 복제 + S3 2차, `amzn-sagemaker-checkpointing` 라이브러리 + `TieredStorageConfig`)은 **Slurm에 없습니다**:

* dev guide가 "**PyTorch frameworks on Amazon EKS HyperPod clusters**"로 명시, 전제조건이 EKS 클러스터 + EKS OIDC IAM, 활성 CLI가 `--orchestrator "Eks={ClusterArn=...}"`.
* GA(2025-09-08) What's New: "currently available for SageMaker HyperPod clusters using the **EKS orchestrator**."

→ Slurm에서 비슷한 효과를 원하면 §4의 자기 구현으로.

### 4. Slurm에서 계층형 체크포인트 직접 구현

```python
# 학습 루프: /fsx에 자주(빠름), S3에 가끔(내구성). PyTorch DCP async_save로 비차단.
from torch.distributed.checkpoint import async_save
fsx_freq, s3_freq = 10, 100
for step in range(num_steps):
    ...
    if step % fsx_freq == 0:
        async_save(state_dict=state, checkpoint_id=f"/fsx/ckpt/step-{step}")   # 1차: 빠른 공유 FS
    # 2차(S3)는 아래 DRA로 자동화하거나, 주기적으로 aws s3 cp
```

**S3 export 자동화 — FSx↔S3 Data Repository Association(DRA)**:

* `/fsx`의 디렉터리(예: `/fsx/ckpt/`)를 S3 prefix에 1:1 매핑. **automatic export**가 앱이 쓴 새/변경 파일을 비동기로 S3에 push.
* FS당 최대 8개 DRA. auto-export는 **콘솔 기본 on, CLI/API 기본 off**. Scratch1 / FSx Lustre 2.10 미지원.

```bash
aws fsx create-data-repository-association \
  --file-system-id fs-0abc... \
  --file-system-path /ckpt/ \
  --data-repository-path s3://my-bucket/checkpoints/ \
  --s3 'AutoExportPolicy={Events=[NEW,CHANGED,DELETED]}'
```
